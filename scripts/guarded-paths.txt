# Guarded Path の一覧(ADR 0011)。Evaluator と改善ループ自身から成る。自己改善ループの PR がここに載ったパスに触れると、
# scripts/check-guarded-paths.sh が CI で失敗させる。人の PR は判定しない。
# 1 行 1 パス(リポジトリルートからの相対)。末尾が / の行はそのディレクトリ配下すべて、
# それ以外は完全一致。+ で始まる行(末尾 / のディレクトリ)は追加だけを許し、ループの PR はそこへ新しい
# ファイルを足せるが、既存のファイルの変更・削除・移動は落とす。# で始まる行と空行は無視する。
#
# Guarded Path を足し忘れたことを機械的に検出する仕組みは無く、足す PR のレビューで確かめる。
# ガードは base 側の版を読むので、足した行はマージ後に効く。

# 改善ループ自身(ADR 0011。解禁の条件も ADR 0011)。ループが自分の抽出・選別・週次ジョブ・状態表示を書き換えると、
# 改善の効果とループの変更の効果を区別できなくなる。ファイル単位で守るので、ループが自分の手順を改善する
# PR も落ちる。これは改善ループ自身を Improvement Surface に含めない決定の帰結として受け入れる。
# harness-review / harness-reflect の SKILL.md と週次ジョブの入口は、識別規約と検出器の節に載せてある。
# 載せないもの: ループの振る舞いを持たない文書(.claude/rules/harness-weekly.md、dot_claude/rules/common/harness-engineering.md、docs/superpowers/ のループの設計書、
# CONTEXT.md のループの用語)。ループの PR がこれらを変えたら、レビューで、記述がこの一覧に載ったファイルの
# 実際の振る舞いと食い違っていないか、ADR 0011・0012 の決定を言い換えて緩めていないかを確かめる。
# settings.json.tmpl も載せない(ループが改善してよい hook と permissions を含む)。briefing と reflect トリガーの

# 配置を見ないので、ループの PR がここに載ったスクリプトを .chezmoiignore に足すと配置が止まり、hook は
# `|| true` で黙って何もしなくなる。ループの PR が .chezmoiignore を変えたら、レビューでこの一覧のパスに
