# サブエージェント(Agent ツール)の運用

Claude Code 専用のルール。`~/.codex/AGENTS.md` には連結しない(Codex に Agent ツールは無い)。

## 長い結果はファイルに書かせ、返信は path と要約だけにする

レビュー・調査・抽出を委譲するときは、プロンプトに「全文は `<scratchpad>/<name>.md` に書き、
返信は判定 1 行・件数・path だけ」と書く。受け取った側はファイルを読んでから対応する。

**理由:** teammate メッセージや idle 通知の `result` は長いと途中で切れる(観測では 16,000 文字前後で切れた)。
切れた後半の再送を頼む往復が 1 件あたり 1〜3 ターンかかり、判定を書いた末尾の節が最後まで届かない。
5 セッション以上で再発し、2026-09-28 の harness-review でも 10 バッチ中 4 バッチが切れた。

## 報告メッセージは終了の証拠ではない

サブエージェントは報告を送った後も動き続けて書き込むことがある。終了の合図は task-notification だけ。
共有ファイルやリポジトリに書かせる委譲では、プロンプトに次の 3 点を入れる。

1. 書き込みがファイルに着地してから報告する
2. 報告後は書かない。訂正が要るなら申告して指示を待つ
3. 作成・変更したファイルの path を報告に列挙する

報告を受けたら、報告された値ではなく実ファイル(存在・件数・mtime)で確かめてから次の作業に進む。
「失敗した」と判断しても、同じ書き込み先に再実行エージェントを重ねる前に生存を確認する。

**理由:** 報告後も生きていたエージェントと再実行エージェントが同じ wiki に並行で書き、
後発が先発のページを「重複」として削除して参照が切れた。

## 完了は通知で届く。待つためにポーリングしない

完了したサブエージェントは task-notification で親を呼び戻す。待つ間はターンを終えるか別の作業をする。
`sleep` で待つ Bash を繰り返さない。Agent の出力ファイル(transcript の JSONL)を Bash で `tail` / `cat` して
進捗を覗かない — 全文がコンテキストに流れ込む。`run_in_background` の Bash も同じ(`bash-tool.md`)。

**理由:** タイムアウトする `sleep` 待ちを 20 回繰り返してセッション上限に達した例がある。

## 回収したら止める

結果を回収して再開の予定が無くなったサブエージェントは `TaskStop` で止める。
ワークフローの完了を報告する前に、生きているサブエージェントが残っていないことを確かめる。

**理由:** subagent-driven development の 4 セッションで、ユーザーが 19〜26 体を手で停止した。
残ったエージェントの idle 通知は数時間遅れてまとめて届き、「既に対応済み」と照合するターンを消費させる。

## サンドボックス解除の裁量をプロンプトで渡さない

委譲プロンプトに「サンドボックスエラー時は無効化して再試行してよい」と書かない。
auto mode の分類器はこの種のプロンプトを拒否し(`[Create Unsafe Agents]` / `[Security Weaken]`)、
委譲そのものが止まる。解除が要るコマンドは通常の権限フローで個別に通す。
Docker のようにサンドボックス内では必ず失敗する作業を渡すときは、親が先に環境を用意するか、
その前提をプロンプトに書く(`bash-tool.md` の Docker 節)。

## subagent-driven development のワークスペースを消さない

終了時に `.superpowers/sdd/<plan>/` を削除しない。git-ignore 済みで害は無い。

**理由:** 繰り延べ項目の台帳がワークスペース内のレビューファイルを参照しており、消すと後から詳細を復元できない。
ユーザーはこの削除を 2 回拒否している。
