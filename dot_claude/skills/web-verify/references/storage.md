# storage — 保存場所の解決・分類・書き込み確認

保存場所を決める順序(明示指定 → 個人設定 → 質問 → 止める)は SKILL.md の「保存場所の決め方」。

個人設定の書式(skill はこのファイルを読むだけで、作成も書き換えもしない):

```json
{ "default": "~/verify/{repo}" }
```

次の解決規則は、明示指定・個人設定・自由入力のどれで得たパスにも適用する。

- 相対パスは対象 worktree のルート(`git rev-parse --show-toplevel`)基準で解決する。
  `.claude/verify` なら worktree ごと(= ブランチごと)のコピーになり、git がブランチを分ける
- `{repo}` は main worktree のディレクトリ名に置き換える。worktree のディレクトリ名は乱数のことがあるので使わない。
  `git rev-parse --path-format=absolute --git-common-dir` の結果の末尾が `/.git` ならその親ディレクトリ名、
  そうでなければ(bare リポジトリ)そのディレクトリ名から末尾の `.git` を除いたもの。
  org が違う同名のリポは同じ `{repo}` になるので、そういうリポがあるならユーザーが設定のパスで分ける
- `~` はホームディレクトリに展開する

決まった保存場所を次のどれかに分類してから先へ進む:

- **スイートがある**: `playwright.config.ts` と `profile.md` がそろっている → 既存スイートへの追加
  (`support/run.ts` が無ければ旧レイアウト。references/scaffold.md の「旧レイアウトの更新」を先に行う)
- **空、または存在しない** → 新規 scaffold
- **それ以外** → 上書きせずに止める。`.DS_Store` と `.web-verify-write-probe` 以外のファイルがあるのに「スイートがある」「空」のどちらにも当たらない場合で、
  ファイル名が scaffold と衝突しなくても、片方だけそろった中断の残骸でも止める。対話中なら、別の場所
  (そのサブディレクトリ・別の空ディレクトリ・`.claude/verify/`)を `AskUserQuestion` で提案してよい。
  ユーザーが明示した場所でも同じ。質問できなければ blocked として報告する

リポの外の保存場所は、サンドボックス(nono / Claude Code の Bash サンドボックス)の書き込み許可の外に
あることが多い。分類の後、scaffold や追加の前に保存場所へ書き込めることを確かめる。保存場所が無ければ
`mkdir -p` が確認を兼ね、あれば空ファイル `.web-verify-write-probe` を作って消す(分類ではこの名前も無視する)。
同じ場所への実行(`test-results/` などの生成)も同じ許可で書けるので、確認は 1 回でよい。
拒否されたら止めて報告する。`dangerouslyDisableSandbox` での再試行や許可の追加は、ユーザーがその場で
明示的に求めたときだけ行う(許可を広げるかはユーザーが決める)。
