# ローカル LLM によるセッション・トリアージ 設計

日付: 2026-08-27
ステータス: 設計レビュー待ち

## 背景・目的

開発合宿(6時間・個人作業)でローカル LLM を用いた開発を行う。合宿側の要件は「ローカル LLM を使うこと」のみで、他に制約はない。個人的な目的は、日常業務が複利で楽になる仕組みを作ることに置く。

対象に選んだのは、harness 改善ループの詰まりである。SessionStart briefing は継続的に以下を警告している。

- 未 reflect セッション **238 件**(`~/.claude/harness/pending.jsonl`)
- 未処理の改善キュー **14 件**(`~/.claude/harness/queue.md`)
- `/harness-review` は一度も実行されていない

詰まりの原因は明確で、`/harness-reflect` は「pending の全件を読んで学びを抽出する」設計である一方、transcript は 1 ファイル最大 29MB・全体で 1.3GB / 2213 ファイルあり、フロンティアモデルの 1 セッションでは物理的に読み切れない。**「大量・低単価・プライベートな一次スクリーニング」という、ローカル LLM がクラウドモデルより構造的に有利な唯一の領域**がここにある。

なお本件は日常業務そのものではなくメタ業務であり、その分だけ直接の効用は遠い。それでも選んだ理由は、(1) 改善が全セッションに効くため複利性が候補中最大であること、(2) 238 件という定量的なバックログが既にあり、効果を数字で測れることによる。

## 前提・制約

| 項目 | 値 |
|---|---|
| マシン | MacBook Air M4 / 24GB / ファンレス |
| 実質使用可能メモリ | Docker(MySQL + MongoDB + Redis)併用時は 12〜14GB 程度。合宿中は Docker を落として 20GB 前後を想定 |
| 現在のローカル LLM 環境 | 未導入(ollama / llama.cpp / LM Studio いずれも無し) |
| 作業時間 | 6 時間(360 分)・個人作業 |
| 成果共有 | 軽い共有程度(口頭・スクショ・Markdown レポートで足りる) |

**ファンレス機での持続推論はサーマルスロットリングを起こす。** バッチ実行中は電源接続を必須とし、実測 tok/s は開始 30 分以内に取る。

## 設計方針

**ローカル LLM を「小さいクラウドモデル」として使わない。** 8B〜14B にコードや文章を書かせる設計は 6 時間では破綻する。採る形は一つに限る。

> **LLM は 1 件につき 1 つの限定的な判断を、JSON スキーマ強制で返すだけ。収集・ループ・重複排除・永続化・整形はすべて決定論的なコードが行う。**

構造化出力(ollama の `format` に JSON Schema を渡す / llama.cpp なら GBNF)が、小さいモデルを実用に足らせる唯一のレバーである。これが無いと 8B は自由記述に流れ、パイプラインが腐る。

## 決定事項サマリ

| 論点 | 決定 |
|---|---|
| ローカル LLM の役割 | 一次スクリーニング(分類)のみ。抽出・文章化はフロンティアモデルに残す |
| 出力先 | `~/.claude/harness/triage.jsonl` に**追記のみ**。`pending.jsonl` は一切触らない |
| モデル | `qwen3:8b` (Q4) から開始し、精度不足なら `qwen3:14b` (Q4) に上げる。同一 gold set で比較する |
| ランタイム | ollama(ゼロから OpenAI 互換エンドポイントに到達するのが最速) |
| 実装言語 | **TypeScript**(依存ゼロ・ビルドなし)。既存の `dot_claude/statusline-command.ts` が `node --experimental-strip-types` で動いている前例に従う。Node v24 系のため型ストリッピングは既定で有効 |
| テスト | `node:test`(標準搭載・追加依存なし)。既存の bats は bash 用のため併用する |
| 評価 | 手ラベル 20 件の gold set。正解率ではなく recall と偽陽性数を別々に追う |
| ベースライン | ①ダイジェスト合計トークン数(算術) ②摩擦シグナル数によるソート の 2 つを対照群として先に測る |
| spec の置き場 | 個人 harness 基盤のため業務リポジトリ外(chezmoi 配下) |
| コードの置き場 | **chezmoi source の `dot_claude/scripts/`**(既存 `harness-*.sh` と同じ場所)。`~/.claude/scripts/` を直接編集しない |
| ランタイム成果物の置き場 | `~/.claude/harness/`(`digests/`, `triage.jsonl`)。2026-07-06 spec の通り chezmoi 管理外 |

## アーキテクチャ

3 層に分割し、ローカル LLM は中央のみを担当する。

```
~/.claude/harness/pending.jsonl  (238 件: session_id / transcript_path / cwd / recorded_epoch)
      │
      ▼
[Layer 1] 決定論・LLM なし — ダイジェスト化
      │   transcript(最大 29MB) → digest(数十KB)。摩擦シグナルの機械的抽出も同時に行う
      ▼
digests/<session_id>.md  +  signals(割り込み回数・エラー数)
      │
      ▼
[Layer 2] ローカル LLM — トリアージ(1 件 1 判断・JSON スキーマ強制)
      │   「学びがあるか」「あるならどこか」だけを答える
      ▼
~/.claude/harness/triage.jsonl   (append-only)
      │
      ▼
[Layer 3] フロンティアモデル(Claude) — 抽出
      │   上位 N 件について、Layer 2 が指した根拠箇所だけを読む
      ▼
~/.claude/harness/queue.md  →  /harness-review  →  PR(既存フロー)
```

### Layer 1: ダイジェスト化(決定論)

transcript の jsonl から、判断に不要な行を捨てる。実測値(29MB / 3927 行のセッション)での内訳は以下の通りで、**`attachment` がサイズの大半を占める**。

```
attachment 2030 / assistant 525 / user 334 / last-prompt 244 / mode 243 /
permission-mode 243 / ai-title 219 / system 70 / ...
```

- **捨てる:** `attachment` / `last-prompt` / `mode` / `permission-mode` / `ai-title` / `file-history-*` / `queue-operation`、および `<command-name>` `<command-message>` `<local-command-stdout>` 等のスラッシュコマンド由来のノイズ
- **残す:** user のテキスト発言、assistant のテキスト、`tool_result` で `is_error` のもの、`[Request interrupted by user]`
- **圧縮率:** 実測で 29MB → 数十KB(約 500 倍)

同時に**摩擦シグナル**を機械的に数える。実データで存在を確認済みのものを使う。

| シグナル | 意味 |
|---|---|
| `[Request interrupted by user]` の出現数 | ユーザーが agent を止めた = 何かがずれていた |
| `tool_result.is_error` の件数 | 試行錯誤の量 |
| user の短い否定的発言 | 訂正・押し戻し |

**ダイジェストにはトークン上限を設ける。** 1 セッションあたり数千トークンで頭打ちにし、摩擦シグナルの周辺を優先して head + tail で切り詰める。切り詰めた事実と量はログに残す(29MB の外れ値がバッチを止めないため)。

### Layer 2: トリアージ(ローカル LLM)

ダイジェスト 1 件につき 1 回だけモデルを呼び、以下のスキーマを強制する。

```json
{
  "has_learning": true,
  "category": "wrong_assumption | user_correction | repeated_attempts | rule_drift | none",
  "severity": "high | medium | low",
  "evidence": "根拠となるダイジェスト中の引用(数行)",
  "one_line": "日本語 1 行の要約"
}
```

**Qwen3 はハイブリッド推論モデルであり、既定で `<think>` ブロックを出力する。** これはレイテンシ予算を大きく変え、制約付き出力とも干渉しうる。0:00-0:30 で thinking の有無を確認し、**測定時とバッチ実行時で同じ設定に固定する**。ここがずれると 238 件の所要時間見積もりが数倍単位で外れる。

判定基準は `harness-reflect` SKILL.md の「What to extract / What NOT to extract」をそのままプロンプトに写す。ただし**同スキルの「迷ったらキューに入れるな」は Layer 2 には適用しない**。Layer 2 は recall 側に倒し、棄却は Layer 3 に任せる(理由は後述)。

**出力は `triage.jsonl` への追記のみとする。** `pending.jsonl` には触れない。これは `harness-reflect` SKILL.md が明記する制約への対応である。

> pending.jsonl は「今存在する状態」に対してフィルタすること。SessionEnd hook が並行して追記するため、以前読んだコピーを書き戻すと、その間に記録されたセッションが黙って失われる。

夜間バッチは全件を読んでから書き戻したくなる典型的な形をしているため、**構造的に書き込ませない**ことで事故を防ぐ。副次的に、バッチが冪等かつ再実行可能になる(プロンプト調整を繰り返す当日の作業で効く)。

### Layer 3: 抽出(フロンティアモデル)

`triage.jsonl` を `has_learning` と `severity` でソートし、上位 N 件について **Layer 2 が指した `evidence` 箇所だけ**を読んで `queue.md` エントリを書く。N は当日の「しきい値決定」(時間割 3:10-3:50)で確定する。目安は 1 回の reflect セッションで読み切れる量、すなわち 20〜30 件。書式・bookkeeping(pending.jsonl の削除、state.json の更新)は既存の `/harness-reflect` の作法をそのまま使う。エントリは既存ルール通り英語で書く。

29MB の transcript を読まずに済むことが、238 件が処理可能になる理由である。

## 検証設計

小さいモデルは**静かに劣化する**。「作った」と「効くと分かっている」を分けるため、パイプラインを書く前に評価基盤を作る。

### gold set

Layer 1 完成直後に 20 件へ二値ラベル(queue に値する学びが有る / 無い)を付ける。

- **ラベルは生 transcript ではなくダイジェストを見て付ける。** モデルが見ない情報を根拠にラベルすると測定が無意味になる
- **内訳: 低シグナル層 14 件(摩擦シグナル数が下位半分のセッションからサンプリング) + 摩擦シグナル上位 6 件。** 層を記録し、集計時に混ぜない

主層を「ランダム」ではなく**低シグナル層**にするのは、証明したい主張がそこにしか存在しないためである。ベースライン②(シグナル数ソート)を上回るとは、**シグナル数では見つからない学びを Layer 2 が拾えること**を意味する。シグナル上位で陽性を当てても、それはベースライン②が既に指している集団であり、優位性を何も示さない。低シグナル層 14 件が主たる根拠であり、シグナル上位 6 件は「明らかな陽性を取りこぼさないか」の確認用に留める。

### 指標

**正解率は使わない。** 陽性のベースレートが低い(skill 自身が「迷ったら入れるな」と規定しており、多数のセッションから出たキューが 14 件)ため、「全部 No」と答えるモデルが高い正解率を取ってしまう。

- **recall(陽性を拾えた割合)** — 主指標
- **偽陽性の件数** — 副指標

運用点は recall 寄りに倒す。コストが非対称なためである。

- 偽陽性のコスト: Layer 3 がダイジェストを 1 件余計に読むだけ
- 偽陰性のコスト: 学びが永久に失われる

### ベースライン(対照群)

ローカル LLM の寄与を数字にするため、以下を先に測る。

1. **ダイジェスト合計トークン数(算術・LLM 呼び出し 0 回)** — Layer 1 完了時点で、238 件のダイジェストのトークン数を合計する。1 件 3k トークンなら約 700k で、1M コンテキストに収まってしまう。**収まるなら Layer 1 だけで実現可能性の問題は解決しており**、Layer 2 の価値は「可能にすること」ではなくコスト・レイテンシ・プライバシーに変わる。**本プロジェクトで最も決定的な数字であり、1:30 時点でタダで得られる。**実験ではなく足し算なので、必ずこの時点で出す
2. **摩擦シグナル数によるソート** — 割り込み回数 + エラー件数で並べるだけの、LLM 不要のプレフィルタ。実装は数行

**Layer 2 はこの 2 つを上回って初めて価値がある。** 上回らなかった場合もその事実を成果として記録する。「ローカル LLM を使った」より「ローカル LLM がベースラインを何ポイント上回った」の方が、共有の中身として強い。

## 時間割(360 分)

| 時間 | 作業 | 打ち切り時の退避 |
|---|---|---|
| 0:00-0:30 | ollama 疎通、JSON スキーマ動作確認、**thinking モードの挙動確認**(下記)、**実ダイジェスト 1 件で tok/s 実測** → 238 件の所要時間を見積もる | 遅ければ対象を 40 件サンプルに縮小 |
| 0:30-1:30 | Layer 1 ダイジェスト化 + 摩擦シグナル抽出(ベースライン②が同時に得られる)。完了時に**ダイジェスト合計トークン数を算出**(ベースライン①) | user 発言のみの簡易ダイジェストに退避 |
| 1:30-2:10 | gold set 20 件を手ラベル | — |
| 2:10-3:10 | Layer 2 分類器 + プロンプト調整、gold set で recall / 偽陽性を実測 | スキーマが不安定なら YES/NO 1 トークン出力に退避 |
| 3:10-3:50 | 8B vs 14B を同一 gold set で比較、しきい値決定 | 時間が無ければ 8B で確定 |
| 3:50-4:50 | 全件バッチ(**バックグラウンド実行・レジューム可能**) → `triage.jsonl` | 40 件で打ち切り |
| 4:50-5:30 | Layer 3 接続 + 日本語レポート生成(バッチと並行可) | queue.md への実投入は 1〜2 件の確認で足りる |
| 5:30-6:00 | 予備・数字のまとめ | — |

**成功の最低ライン:** 238 件のダイジェスト化が完了し、ローカル LLM で 40 件以上を分類でき、gold set に対する数字(recall・偽陽性数)が出ていること。全件バッチと Layer 3 接続は上振れとする。

## 事前準備(前夜までに必須)

1. ollama を導入する
2. `qwen3:8b` と `qwen3:14b` を pull する

**会場の Wi-Fi で 5〜9GB を落とすと 6 時間のうち 1 時間が溶ける。** 重みの取得は必ず事前に済ませる。

## 手元に残る数字(共有用)

1. ベースライン(シグナル数ソート) vs ローカル LLM の recall / 偽陽性
2. 8B vs 14B の比較
3. 238 件の処理時間と実測 tok/s
4. ダイジェストの圧縮率(29MB → 数十KB)

## スコープ外(YAGNI)

- **ファインチューニング** — 6 時間に入らない
- **埋め込み / RAG による過去セッション検索** — 別案として検討したが、品質評価が 6 時間では成立せず、悪くても悪いと気づけない
- **hook からのリアルタイム判定** — 複利は最大だが、Air + 8B で 1 判定 2〜5 秒、誤検知が出た瞬間に開発体験が壊れる。チューニング時間が足りない
- **ローカル LLM に queue.md エントリ本文を書かせること** — 文章品質は Layer 3 が担保する
- **`pending.jsonl` の自動削除** — 既存フローに任せる

## リスク

| リスク | 対応 |
|---|---|
| スループット不足で 238 件が終わらない | 開始 30 分で tok/s を実測し、40 件サンプルに縮小するか初回の夜間実行に回す |
| 小さいモデルが静かに劣化する | gold set をパイプラインより先に作る |
| ファンレス機のサーマルスロットリング | 電源接続。バッチはバックグラウンド + レジューム可能に |
| 陽性のベースレートが低すぎて評価不能 | 摩擦シグナル上位を層化して gold set に混ぜる(層は分けて集計) |
| `pending.jsonl` の破壊 | Layer 2 を append-only とし、構造的に書き込ませない |
