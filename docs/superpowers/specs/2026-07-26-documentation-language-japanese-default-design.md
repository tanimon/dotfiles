# ドキュメント言語ポリシーの日本語デフォルト化 — Design

**Date:** 2026-07-26
**Status:** Approved (pending user review of this document)
**Module:** `dot_claude/rules/common/documentation-language.md`

## Context

`dot_claude/rules/common/documentation-language.md` は、PR #91（2026-03-29）でエージェント向けドキュメントを英語に統一する目的で導入されたルール。対象は `CLAUDE.md`/`AGENTS.md`、`.claude/rules/**/*.md`、`docs/solutions/**/*.md`、コードコメント、コミットメッセージで、根拠は「LLMの学習データは英語中心であり、英語の方が解釈精度が高い」だった。

このルールを見直し、基本方針を日本語に転換したい、というのが今回の依頼。最新のLLM（Sonnet 5など）は日本語も高精度で扱えるため、解釈精度上のトレードオフは小さく、最終的にドキュメントを読む人間（日本語話者であるユーザー）の可読性を優先すべき、という判断による。

## Decision

### 対象範囲

現行ルールが列挙する全カテゴリを日本語デフォルトに転換する:

- `CLAUDE.md` / `AGENTS.md`
- `.claude/rules/**/*.md`
- `docs/solutions/**/*.md`
- コードコメント
- コミットメッセージ

### 適用範囲（時間軸）

**今後新規作成するドキュメントにのみ適用する。** 既存の英語ドキュメント（`CLAUDE.md` の Known Pitfalls、`docs/solutions/**`、`docs/superpowers/specs/**` など）の一括翻訳は行わない。編集の機会があっても逆翻訳を強制しない。

一方、既存の英語ドキュメントに新規項目を追記・編集する場合、追記部分そのものは日本語で記載する（ファイル全体の一括翻訳は行わない。1ファイル内で英語と日本語が混在する状態を許容する）。

例外として、今回のルール変更対象である `documentation-language.md` 自体は、この編集の一環として日本語に書き直す（一括翻訳の対象ではなく、まさに今手を入れる1ファイルの自然な編集）。

### 例外（英語での記載を許容する場合）

1. **明示的に英語での記載を指示された場合** — その指示に従い英語で記載する
2. **Skillなどの出力フォーマットでセクション名や構造が英語で指定されている場合** — 指定された構造部分（セクション名、フロントマターのキー名、Conventional Commitsの `feat:`/`fix:` などのtype等）はそのまま英語を使う。本文の言語について特に指定がなければ、本文は日本語で記載する

### 削除する内容

現行ルールの「Exceptions」にあった「PRの説明文」「チャットでの応答」は削除する。これらはそもそも基本ルールが列挙する対象カテゴリ（ドキュメントファイル・コードコメント・コミットメッセージ）に含まれておらず、「例外」として言及する必要がない。

```markdown
# ドキュメントの言語

## 新規ドキュメントは日本語で記載する

新規作成時は以下を日本語で記載する:

- `CLAUDE.md` / `AGENTS.md` — プロジェクト指示
- `.claude/rules/**/*.md` — ルールファイル
- `docs/solutions/**/*.md` — 解決策ドキュメント
- コードコメント
- コミットメッセージ

既存の英語ドキュメントに新規項目を追記・編集する場合も、追記部分は日本語で記載する（ファイル全体の一括翻訳は行わない。1ファイル内で英語と日本語が混在する状態を許容する）。

**理由:** これらのドキュメントは最終的に人間（日本語話者）が読むもの。最新のLLM（Sonnet 5など）は日本語も十分な精度で扱えるため、英語で書くことによる解釈精度上のメリットは小さく、人間の可読性を優先すべき。

**例外（英語での記載を許容する場合）:**

- **明示的に英語での記載を指示された場合** — その指示に従い英語で記載する
- **Skillなどの出力フォーマットでセクション名や構造が英語で指定されている場合** — 指定された構造部分（セクション名、フロントマターのキー名、Conventional Commitsの `feat:`/`fix:` などのtype等）はそのまま英語を使う。本文の言語について特に指定がなければ、本文は日本語で記載する
```

`date` フィールドは他のルールファイル（`harness-engineering.md`, `github-actions.md`）の慣例に合わせ、内容変更時にも作成日のまま据え置く。

## Out of Scope

- 既存の英語ドキュメントの一括翻訳（別途、必要になった時点で個別に検討する）
- `documentation-language.md` 以外の既存ルールファイルの日本語化
