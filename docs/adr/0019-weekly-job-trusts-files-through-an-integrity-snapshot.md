# 週次ジョブは claude の後に使うファイルを Integrity Snapshot の入口を通してだけ信頼する

週次ジョブ(`harness-weekly.sh`)の抽出と選別の claude は `--dangerously-skip-permissions` で動き、`~/.claude` に書ける。claude の後に job が使う Evaluator のスクリプトや記録を claude が書き換えると、評価や記録を偽れる。これまでは claude の起動前にハッシュを取る一覧が 3 本に分かれ、照合も 3 か所で返す値がそろわず、「どのスクリプトを呼ぶ前にどの照合を済ませるか」が呼び出しの順序でしか決まっていなかった。そのため照合を通らない呼び出しが残り、ハッシュを取れないときに公開が続く経路もあった(#514)。そこで照合を `dot_claude/scripts/lib/harness-integrity.bash` の 1 つの module(Integrity Snapshot)に集め、一覧の正本をそこに 1 本だけ置く。claude の後に `~/.claude/scripts` のスクリプトを呼ぶときは必ず module の入口を通し、入口は実行の直前に実行物の全部を比べる。改ざん・削除・照合不能はどれも予約コード 3 で返し、push と `gh pr create` の直前にも実行物を比べる関門を置く。

## Considered Options

- **信頼するスクリプトを複製して、複製の方を実行する** — 却下。複製の置き場所も claude が書ける境界の内側にしか取れない。`BASH_SOURCE` や `$HOME/.claude/scripts` を基準にファイルを引くスクリプトも壊れる。
- **claude が終わった直後に 1 回、全部をまとめて比べる** — 却下。改ざんを見つけたときの結果はどの照合点でも「PR を作らない」なので振る舞いは同じだが、claude が残したバックグラウンドのプロセスは照合の後でも書き換えられる。使う直前に比べるしか防げない。
- **入口で毎回、実行物とデータの全部を比べる** — 却下。claude の後に job 自身が正当にデータを書く(`rule-ledger` の `record` と `export`)ので、全部を比べるとそれを改ざんと区別できない。実行物は入口で毎回、データは各 claude の後(job 自身が書く前。repo に写す工程を通らずに終わる run があるため)と、repo に写す直前・記録を作る直前に比べ、信頼する入口が書いたファイル(評価の結果、`record` が作った記録)は後から封印して一覧に足す。
- **照合に落ちたことを、スクリプト自身の失敗と同じ終了コードで返す** — 却下。スクリプトの失敗を WARN にして公開を続ける呼び出し元があり、`section=$(…)` の内側はサブシェルなのでフラグを立てても戻らない。信頼するスクリプトが使わない予約コードで区別し、取りこぼしに備えて公開の直前にも関門を置く。
- **スナップショットの前に入口を使ったら、照合を飛ばしてそのまま実行する** — 却下。順序を取り違えても黙って通る。失敗させれば取り違えがすぐ分かる。
- **実行時の一覧を `scripts/guarded-paths.txt` と統合する** — 却下。CI の一覧はループの PR が変えてはいけないパスで、実行時の一覧は claude の後に job が使うファイルなので意味が違う。代わりに、実行時の一覧にある実行物の Source がすべて Guarded Path に載っていることを bats で確かめる。

## Consequences

- 一覧の基準は「claude の起動後に job が実行する・読み込む・commit するファイルの全部」で、module のヘッダに書く。新しいスクリプトを claude の後に呼ぶときは、module の一覧に足さないと入口が実行を拒む。
- EXIT trap の `report_stops` は、入口を使えない run(lib の読み込みかスナップショットの前に止まった)と照合に落ちた run では Verdict の CLI を呼ばない。ブランチの Issue は作り、本文に「Verdict CLI を確かめられなかった」か「信頼できなかった」と書く。lib の読み込みに失敗した run は、それ自体が失敗の Issue で知らされる。
- PR を作った後(判定の記録の URL への置き換えと Rule Ledger の記録)に照合に落ちた run は、PR を残したまま失敗する(heartbeat を書かない)。
- 週次ジョブ本体の書き換えは守れない。bash はスクリプトを実行しながら読むので、claude が書き換えるとその run の残りが変わりうる。照合と実行の間、`record` と封印の間の書き換えも残存リスクとして module のヘッダに書く。
